# Database Guide - Subsea Pipeline Integrity Monitoring System

This document provides a complete guide to the MySQL database schema, relationships, permissions, and inspection procedures for the **Database Host** (Student 2 co-deliverable).

---

## 1. Database Specifications

* **Database Engine**: MySQL Server 8.0+ (InnoDB Storage Engine)
* **Default Port**: `3306`
* **Database Name**: `subsea_pipeline`
* **Character Set**: `utf8mb4`
* **Collation**: `utf8mb4_unicode_ci`

---

## 2. Table Schemas & Relational Design

The database consists of four tables enforcing relational integrity via foreign key constraints (`ON DELETE CASCADE ON UPDATE CASCADE`).

```
+-------------------------------------------------------------------------+
|                              pipe_segments                              |
+-------------------------------------------------------------------------+
| PK  | segment_id        | INT AUTO_INCREMENT                            |
| UQ  | segment_code      | VARCHAR(30) UNIQUE NOT NULL                   |
|     | category          | VARCHAR(50) NOT NULL                          |
|     | subsea_depth_m    | DECIMAL(10,2) NOT NULL                        |
|     | wall_thickness_mm | DECIMAL(10,2) NOT NULL                        |
|     | fluid_type        | VARCHAR(50) NOT NULL                          |
|     | maop_psi          | DECIMAL(10,2) NOT NULL                        |
|     | created_at        | TIMESTAMP DEFAULT CURRENT_TIMESTAMP           |
+-------------------------------------------------------------------------+
       │                      │                             │
       │ 1:N                  │ 1:N                         │ 1:N
       ▼                      ▼                             ▼
+---------------------+ +----------------------+ +-------------------------+
|   pig_inspections   | |   corrosion_audits   | |      repair_orders      |
+---------------------+ +----------------------+ +-------------------------+
| PK | inspection_id  | | PK | audit_id        | | PK | repair_id          |
| FK | segment_id     | | FK | segment_id      | | FK | segment_id         |
|    | wall_loss_%    | |    | upstream_flow   | |    | hazard_code        |
|    | cathodic_volt  | |    | downstream_flow | |    | integrity_score    |
|    | int_pressure   | |    | acoustic_hz     | |    | integrity_grade    |
|    | inspection_dt  | |    | hydrophone_sc   | |    | rupture_risk_fac   |
|    |                | |    | audit_date      | |    | action_required    |
|    |                | |    |                 | |    | repair_date        |
+---------------------+ +----------------------+ +-------------------------+
```

### Table 1: `pipe_segments`
Stores physical and engineering specifications for underwater pipeline segments.
* `segment_id`: Primary Key (Auto Increment).
* `segment_code`: Unique identifier (e.g., `PIPE-SUB-00001`).
* `category`: Pipeline category (`HIGH_PRESSURE_DEEPWATER`, `SHALLOW_COASTAL_TRUNK`, `LIQUEFIED_GAS_FEEDER`).
* `subsea_depth_m`: Bathymetric seabed depth in meters.
* `wall_thickness_mm`: Nominal pipe wall thickness in millimeters.
* `fluid_type`: Fluid type transported (`CRUDE_OIL`, `NATURAL_GAS`, `LIQUEFIED_GAS`).
* `maop_psi`: Maximum Allowable Operating Pressure in pounds per square inch.

### Table 2: `pig_inspections`
Stores in-line inspection (ILI) telemetry collected by smart PIG tools traversing the pipeline bore.
* `inspection_id`: Primary Key.
* `segment_id`: Foreign Key referencing `pipe_segments(segment_id)`.
* `wall_loss_percent`: Highest detected metal loss percentage (0.00% to 100.00%).
* `cathodic_voltage_v`: Cathodic protection potential measured in Volts.
* `internal_pressure_psi`: Real-time operational internal fluid pressure in PSI.
* `inspection_date`: Telemetry timestamp.

### Table 3: `corrosion_audits`
Stores acoustic sensor telemetry and volumetric mass flow balance data.
* `audit_id`: Primary Key.
* `segment_id`: Foreign Key referencing `pipe_segments(segment_id)`.
* `upstream_flow_bpd`: Inlet fluid flow rate in Barrels Per Day (BPD).
* `downstream_flow_bpd`: Outlet manifold fluid flow rate in BPD.
* `acoustic_leak_hz`: Peak frequency detected by acoustic telemetry sensors.
* `hydrophone_noise_score`: Normalized seabed hydrophone background noise score (0 to 100).
* `audit_date`: Audit timestamp.

### Table 4: `repair_orders`
Stores actionable maintenance and remediation orders generated by Student 1's Java application.
* `repair_id`: Primary Key.
* `segment_id`: Foreign Key referencing `pipe_segments(segment_id)`.
* `hazard_code`: Standard hazard classification (e.g. `HAZ-CRIT-RUPTURE`, `HAZ-CORR-SEVERE`, `HAZ-NOMINAL`).
* `integrity_score`: Computed Pipeline Condition Index (PCI 0.00 to 100.00).
* `integrity_grade`: Letter grade (`A`, `B`, `C`, `D`, `F`).
* `rupture_risk_factor`: Calculated risk factor (`0.0001` to `0.9999`).
* `action_required`: Detailed engineering directive (e.g. ROV survey, clamp installation, pressure derating).
* `repair_date`: Timestamp when the repair order was generated.

## 3. Database Security & User Management

To adhere to security best practices and prepare for OCI VM deployment, the Java application does not connect as `root`. A dedicated application user is configured:

```sql
-- Create application user with restricted privileges
CREATE USER IF NOT EXISTS 'subsea_app'@'%' IDENTIFIED BY 'SubseaApp@2026#ChangeMe';

-- Grant required DML permissions on application schema only
GRANT SELECT, INSERT, UPDATE, DELETE ON subsea_pipeline.* TO 'subsea_app'@'%';

-- Refresh privilege tables
FLUSH PRIVILEGES;
```

## 4. Useful Inspection Queries (MySQL Workbench)

Run these queries in MySQL Workbench to verify database state:

```sql
USE subsea_pipeline;

-- 1. View all pipe segments
SELECT * FROM pipe_segments;

-- 2. View telemetry data alongside segment codes
SELECT p.segment_code, p.category, i.wall_loss_percent, i.internal_pressure_psi, c.acoustic_leak_hz
FROM pipe_segments p
LEFT JOIN pig_inspections i ON p.segment_id = i.segment_id
LEFT JOIN corrosion_audits c ON p.segment_id = c.segment_id;

-- 3. View latest repair orders generated by the Java application
SELECT r.repair_id, p.segment_code, r.hazard_code, r.integrity_score, r.integrity_grade,
       r.rupture_risk_factor, r.action_required, r.repair_date
FROM repair_orders r
JOIN pipe_segments p ON r.segment_id = p.segment_id
ORDER BY r.repair_date DESC;

-- 4. Verify foreign key constraints
SELECT TABLE_NAME, COLUMN_NAME, CONSTRAINT_NAME, REFERENCED_TABLE_NAME, REFERENCED_COLUMN_NAME
FROM INFORMATION_SCHEMA.KEY_COLUMN_USAGE
WHERE TABLE_SCHEMA = 'subsea_pipeline' AND REFERENCED_TABLE_NAME IS NOT NULL;
```
